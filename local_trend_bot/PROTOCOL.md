# Окремий локальний trend-bot: протокол v1, 08.10.2026

Записано до розрахунку НОВИХ правил на наявних даних. Історія вже
переглядалася в інших дослідженнях; це не сліпий out-of-sample.
Параметри після результату не змінювати. Старий VWAP не переписувати.

Два незмінні кандидати BTCUSDT/ETHUSDT Spot, денні UTC свічки:
1. Donchian: Close вище максимуму попередніх55 High -> long;
   Close нижче мінімуму попередніх20 Low -> cash; інакше стан зберігається.
2. Momentum365: Close вище Close365 днів тому -> long, інакше cash.

Одна повна денна свічка затримки: рішення дня t виконується на Open t+2.
Ніяких short, плеча, усереднення або AI-рішень. Окремі результати двох
активів; не вибирати переможця після тесту. Віртуальний капітал1000,
два ізольовані кошики500. Це не доступ до реального рахунка.

Кеш публічних даних2019–30.09.2026. Оцінка2020–2023 та2024–30.09.2026;
кожен блок починає в cash, warmup лише для сигналів. Витрати0.1% на
сторону, stress0.3%; конечна ліквідація по Close з тими ж витратами.
Контроль hold і cash/hold зі сталою долею, рівною фактичній середній
експозиції кандидата; matched-control не є причинним торгованим правилом.

Gate для статусу candidate (не дозвіл на реальні гроші): ОБИДВА активи
в пізньому блоці мають позитивний stress-return, DD не гірше−25%,
і нижню95% межу paired bootstrap середнього денного log-excess над
matched-control >0. Circular blocks30d,1000 повторів, seed20261008;
Bonferroni нижня межа для ДВОХ правил: quantile0.0125. Не приховувати
жоден провал. 25% — дослідницький gate, не узгоджений ризик власника.

Навіть проходження gate потребує незалежних даних/forward-перевірки.
Bot без параметра --diagnostic-paper лише збирає рішення і статус;
віртуальні угоди відхиленого кандидата можливі тільки як явно позначений
діагностичний forward, не рекомендація. API тільки public GET на
data-api.binance.vision, без env/config/Supabase/брокерських імпортів.
Hard timeout whole fetch-child45s, нічого не торгувати при stale/gap/
некоректних даних. Повтор одного UTC-дня не створює дубль угоди.
